# Deployment

A free deployment in three parts: MongoDB Atlas for the database, Render for the API and Vercel for the frontend.

| Part | Live URL |
|---|---|
| Frontend (Vercel) | https://triad-dms.vercel.app |
| API (Render) | https://triad-dms-api.onrender.com/api |
| Health check | https://triad-dms-api.onrender.com/api/health |

```
Browser ──> Vercel (React build) ──/api/*──> Render (Flask API, Docker) ──> MongoDB Atlas (records + GridFS)
```

The frontend keeps calling relative `/api` URLs. Vercel forwards them to Render (`frontend/vercel.json`), so the browser only ever talks to one origin and no CORS setup is needed for the app to work.

Do the steps in this order: Atlas, Render, Vercel, then load the demo data.

## 1. MongoDB Atlas

1. Sign in at [cloud.mongodb.com](https://cloud.mongodb.com) and create a project, e.g. `triad-dms`.
2. **Create** a cluster: choose **M0 (Free)**, provider **AWS**, region **Singapore (ap-southeast-1)** to sit next to the Render service. Click **Create Deployment**.
3. In the **Connect to Cluster0** dialog, create a database user. Use a password without `@`, `:` or `/` (or URL-encode it later). Save the username and password.
4. Left menu, **Security > Network Access > Add IP Address > Allow Access from Anywhere** (`0.0.0.0/0`) **> Confirm**. Render's free plan has no fixed outbound IP, so Atlas has to accept any address; the database user and password still protect it. This also lets your laptop load the demo data.
5. **Database > Clusters > Connect > Drivers**. Copy the connection string and put your password in it:

   ```
   mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```

   No database name is needed in the string; the API uses `MONGO_DB=triad_dms`. This full string is your **Atlas URI** for the next steps.

## 2. Render (API)

The repository has a Blueprint, [`render.yaml`](../render.yaml), that defines one Docker web service named `triad-dms-api` on the free plan in Singapore, with health check `/api/health`.

1. Sign in at [dashboard.render.com](https://dashboard.render.com) with GitHub.
2. **New > Blueprint**. Connect GitHub if asked, and pick the `Triad-dms` repository. Click **Connect**.
3. **Blueprint Name**: `triad-dms`. Branch: `main`. Render reads `render.yaml` and lists the `triad-dms-api` web service.
4. Render asks for the three values marked `sync: false`:

   | Key | Value |
   |---|---|
   | `MONGO_URI` | your Atlas URI |
   | `ADMIN_PASSWORD` | a strong password for `admin@example.com`; keep it, the demo seed needs it |
   | `CORS_ORIGINS` | `https://triad-dms.vercel.app` (the live frontend; use your own Vercel URL if it differs) |

   `JWT_SECRET` is generated by Render. The other settings come from the Blueprint: `MONGO_DB=triad_dms`, `GUNICORN_WORKERS=2`, `ALLOW_ANONYMOUS_UPLOAD=false`, `OCR_ENABLED=true`, `BCRYPT_ROUNDS=10`, `ADMIN_EMAIL=admin@example.com`.
5. Click **Apply** (or **Deploy Blueprint**). The first build takes 5 to 10 minutes because the image installs Tesseract. In the service's **Logs**, wait for `Seed complete` and `Listening at: http://0.0.0.0:10000`.
6. Open `https://triad-dms-api.onrender.com/api/health`. It should return `{"status": "ok", "database": "ok", "ocr": {"status": "available", ...}}`.

If Render shows a different URL at the top of the service page (it adds a suffix when the name is taken), change the destination in `frontend/vercel.json` to that URL and push before deploying the frontend.

Values entered in step 4 are only asked for when the Blueprint is first created. To change them later, open the service, **Environment**, edit, **Save Changes**; Render redeploys.

## 3. Vercel (frontend)

1. Sign in at [vercel.com](https://vercel.com) with GitHub.
2. **Add New... > Project**, then **Import** the `Triad-dms` repository.
3. On **Configure Project**:
   - **Root Directory**: click **Edit**, choose `frontend`, **Continue**.
   - **Framework Preset**: Vite (detected). Build command `npm run build` and output directory `dist` are the defaults; leave them.
   - No environment variables are needed.
4. Click **Deploy**. When it finishes, open the URL Vercel shows. The live deployment is at `https://triad-dms.vercel.app`.
5. If that URL differs from the `CORS_ORIGINS` you gave Render, update `CORS_ORIGINS` on Render (step 2, last paragraph).

`frontend/vercel.json` sends `/api/*` to the Render API and every other path to `index.html`, so links such as `/documents/<id>` work on refresh. Real files (scripts, styles, images) are served before the rewrites apply.

## 4. Load the demo data into Atlas

Run this on your laptop, from the project folder, with Docker running. It uses the backend image from `docker-compose.yml`, but points it at Atlas:

```bash
docker compose run --rm \
  -e MONGO_URI="<your Atlas URI>" \
  -e ADMIN_PASSWORD="<the ADMIN_PASSWORD you set on Render>" \
  -e BCRYPT_ROUNDS=10 \
  backend python -m app.demo_seed --reset
```

On PowerShell, put it on one line (or replace each trailing `\` with a backtick).

- `-e MONGO_URI` overrides the local `mongodb://mongo:27017` that `docker-compose.yml` sets for the backend. The first line the seed prints is the target, without credentials, e.g. `Database: mongodb+srv://cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0 (triad_dms)`. If it says `mongodb://mongo:27017`, stop: the override didn't apply.
- `-e ADMIN_PASSWORD` must match Render. Render created the admin on its first start, and the seed signs in as that admin to upload the Headquarters documents. With a different password the seed stops before changing anything.
- `-e BCRYPT_ROUNDS=10` matches Render, so the demo users' sign-ins are quick on the free CPU.
- Docker Compose also starts the local MongoDB container because the backend depends on it. Nothing is written to it.

OCR runs on your laptop and the files go to Atlas GridFS. It takes about a minute and ends with the same summary as a local run: 4 members, Demo Admin, 14 documents, access requests in every state.

Then open the Vercel URL and sign in as `asha.verma@example.com` / `Demo@12345`, or as `demo.admin@example.com` / `Demo@12345` for the admin screens. Demo Admin is a shareable admin created by the seed and promoted by the real super admin; `admin@example.com` and your Render `ADMIN_PASSWORD` stay private.

To refresh the demo later, run the same command again; `--reset` replaces the demo documents, users (including Demo Admin), requests and audit log, and keeps the super admin, divisions and fields.

## Free tier notes

- **Render sleeps after 15 minutes without traffic.** The next request wakes it, which takes about a minute. Vercel waits up to 120 seconds for the API, so the first page load is slow rather than broken. Before a demo, open `https://triad-dms-api.onrender.com/api/health` and wait for it to answer.
- **Memory (512 MB).** Two gunicorn workers idle at about 126 MB in total. Measured peaks with this configuration: 226 MB for a 6-page scanned PDF and 348 MB for a 63-megapixel JPEG. Large images are scaled down before OCR, PDFs empty MuPDF's image cache after each page, and freed buffers go straight back to the OS. Two very large scans uploaded at the same moment are the one case that could approach the limit; Render restarts the service if it ever runs out.
- **CPU (0.1 of a CPU).** OCR of scanned pages is much slower than on a laptop, often 10 to 30 seconds per page. PDFs with a text layer are fast.
- **Uploads go through Vercel's proxy.** Vercel doesn't document a body size limit for rewrites to external URLs. Small and typical scans work; if a large upload (towards the 25 MB API limit) fails on the live site, the proxy is the likely cause.
- **Anonymous uploads are off** on Render (`ALLOW_ANONYMOUS_UPLOAD=false`), so run the evaluators' `test_api.py` against a local stack, not the live API.
- **Client IPs.** Behind Vercel and Render, the API sees the proxy's address. Audit log IPs show that address, and the failed-login limit (10 per minute) is shared by everyone signing in through the proxy.
- **Atlas M0** has 512 MB of storage. The demo data uses a few MB.
- **Redeploys.** Render and Vercel both redeploy on every push to `main`.
